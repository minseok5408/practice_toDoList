### 문제 원인과 수정 내용

- Android 13 이상에서는 앱 알림이 기본적으로 꺼져 있으며 `POST_NOTIFICATIONS` 런타임
  권한을 사용자가 허용해야 배너와 알림 목록을 표시할 수 있습니다.
- 이전 버전은 알림 시간이 있는 할 일을 저장할 때만 권한을 요청했기 때문에 최초 접속에서는
  알림 권한 안내가 보이지 않았습니다.
- 1.0.4에서는 최초 메인 화면에서 마감 알림에 권한이 필요한 이유를 먼저 안내하고,
  사용자가 `허용`을 선택할 때 Android 시스템 권한 창을 요청하도록 수정했습니다.
- 이미 알림 권한이 허용된 기기에서는 안내를 생략하며, 안내 처리 여부를 로컬 설정에 저장해
  앱을 다시 실행할 때 반복 표시하지 않습니다.
- 네이티브 설정에 `android.permission.POST_NOTIFICATIONS`와
  `android.permission.SCHEDULE_EXACT_ALARM`을 명시했습니다.

### 실제 실행 검증

- 환경: Android 15(API 35), 공식 Android Emulator, `x86_64`
- 데이터를 초기화한 가상 기기에 1.0.4 APK만 설치
- 설치 직후 `POST_NOTIFICATIONS: granted=false` 확인
- 온보딩 완료 뒤 `Allow task reminders?` 앱 안내 표시 확인
- 앱 안내의 `Allow` 선택 뒤 Android 공식 권한 창 표시 확인
- 시스템 `Allow` 선택 뒤 `POST_NOTIFICATIONS: granted=true` 확인
- 앱 강제 종료·재실행 뒤 메인 화면과 프로세스 유지 확인
- 재실행 시 앱 안내와 시스템 권한 창이 다시 표시되지 않음을 확인
- 전 과정의 Android crash 버퍼가 비어 있음을 확인

### 개선 방향

- 설정 화면에 현재 알림 권한 상태와 기기 앱 알림 설정으로 이동하는 버튼을 추가할 수 있습니다.
- Android 제조사별 배터리 최적화가 예약 알림을 지연시키는 경우를 실제 ARM64 기기에서
  추가 확인합니다.
- iOS에서도 동일한 사전 안내와 Apple 시스템 알림 권한 흐름을 실제 기기에서 검증합니다.

### 실제 실행 검증

- 환경: Android 15(API 35), 공식 Android Emulator, `x86_64`
- 앱 완전 삭제 후 `moment-1.0.2-android.apk` 파일만 설치
- 온보딩 세 단계와 메인 할 일 화면 표시 확인
- 할 일, 달력, 기록, 보관함, 설정 탭 표시 확인
- 새 할 일 화면에서 마감일 기본값이 당일 23:59로 표시되는 것 확인
- 앱을 강제 종료한 뒤 다시 실행해 메인 화면과 프로세스 유지 확인
- PC의 개발 서버, Expo Go 또는 개발 클라이언트 없이 검증

### 실패 원인과 수정 내용

1. 1.0.1 APK에는 ARM 32비트/64비트 라이브러리만 있어 `x86_64` 환경에서
   `libreactnative.so`를 찾지 못하는 시작 충돌을 재현했습니다.
2. 네 가지 CPU를 넣은 첫 1.0.2 시도에서는 시작 직후
   `[Worklets] Only worklets can be executed synchronously on UI runtime` 오류를 재현했습니다.
3. 시작 시 Worklets/Reanimated에 의존하던 드래그·스와이프 목록을 React Native 기본
   `FlatList`와 명시적인 위·아래·삭제 버튼으로 교체했습니다.
4. `react-native-reanimated`, `react-native-worklets`,
   `react-native-draggable-flatlist` 의존성을 제거하고 네 가지 CPU 라이브러리를 포함했습니다.
5. 온보딩 설명도 실제 버튼 조작과 일치하도록 수정했습니다.

### 남은 범위와 개선 방향

- Android 7 이상과 네 가지 주요 CPU ABI를 포함해 최근 일반 Android 기기의 설치 범위를
  넓혔지만, 모든 제조사·OS 조합을 한 번의 에뮬레이터 검사로 보증할 수는 없습니다.
- 다음 배포 전에는 ARM64 실제 기기 한 대 이상에서도 설치, 알림 권한, 백업·복원을 확인합니다.
- 이 APK는 직접 전달·테스트용 디버그 인증서로 서명되었습니다. 스토어 배포 전에는 전용
  릴리스 키와 Google Play App Signing을 사용합니다.

## 1.0.1

### 성공 여부

- 릴리스 빌드와 APK 서명: 성공
- 사용자 기기 설치: 성공
- 사용자 기기 최초 실행: 실패 — 흰 화면 직후 종료
- `x86_64` Android 15 재현: 실패 — `SoLoaderDSONotFoundError`, `libreactnative.so` 누락
- 배포 상태: 중단

### 실패 원인과 개선 방향

- APK가 `arm64-v8a`, `armeabi-v7a`만 포함해 CPU 호환 범위가 제한됐습니다.
- 같은 시작 코드를 네 가지 CPU로 빌드한 검사본에서 Worklets UI runtime 충돌도 확인했습니다.
- 1.0.2에서 네 가지 ABI를 포함하고 Worklets 기반 시작 경로를 제거했습니다.
- 1.0.1 APK는 더 이상 배포하지 않습니다.

- 설치: 성공

- 배포 상태: 중단

- 1.0.1에서 개발용 런처 의존성을 제거했지만 별도의 시작 충돌이 남았고, 최종 수정은
  1.0.2에 반영했습니다.
